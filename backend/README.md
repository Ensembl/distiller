
## Getting started 

To run the distiller backend locally you need the following three things

1. The backend setup  - 
2. At least one duckdb generated by the ETL
3. A config file

### Setup

Distiller uses 'UV' to manage dependencies and environments. To get started call 'uv sync' in the root backend directory `/my/clone/path/distiller/backend`

### Datasets

Distiller is a data-driven tabular data viewer. This means in order to run the backend you will need to generate at least one dataset. You can do this by using the 'ETL'. 

An example dataset config is provided with the `ETL` which can be used to generate a dataset with the following

```bash
uv run python main.py -r example_v1 -c example/config.json -d example/data.json
```

### Config

The backend server needs to know what datasets are available. Currently this is done with a config file.  

`config.json.example` can be used as a template for this config file 

```json
{
    "datasets":[
        {
            "id":"unique name",
            "label":"My dataset",
            "path":"/my/dataset/path/data.duckdb"
        }
    ]
}
```

The backend tries to get the location of this file from a environmental variable called `DISTILLER_CONFIG`. If this variable is not set then it will default to the current working directory.

### Starting the backend

The distiller backend uses `uvicorn` as its application server. It can be started locally using 

`uv run uvicorn --host 0.0.0.0 --port 8000 main:app`

## Endpoints 

### /datasets

returns a list of datasets 

```json
{"datasets":[
	{"label":"Genes","id":"gene"},
	{"label":"Example","id":"example"}
	]
}
```
